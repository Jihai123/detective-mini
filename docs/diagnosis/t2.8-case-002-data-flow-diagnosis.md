## 1. selector 卡片视觉（Bug 1）

### 根因

`CaseMeta` 类型（`src/cases/types.ts:3-10`）没有 `hero`、`marketingMeta` 或任何封面图字段。selector 渲染卡片时，封面图只在 `isMain === true`（即 `meta.order === 1`）时才渲染：

```typescript
// src/case-selector/case-selector.ts:51
const isMain = meta.order === 1;

// 第 57 行：只有 isMain 时才输出封面 div
${isMain ? `<div class="directory-card-cover"
  style="background-image:url('/assets/cases/${meta.id}/scenes/archive_cover.jpg')"></div>` : ''}
```

- **case-001**（order=1, isMain=true）：渲染 `directory-card-main` class + 封面 div（使用 `archive_cover.jpg`）+ `<h2>` 标题。
- **case-002**（order=2, isMain=false）：无封面 div，无 hero 图，只有 `<h3>` 标题和按钮。

`/assets/cases/case-002/scenes/archive_cover.jpg` 这个路径从未被引用到卡片渲染里。

### 字段值

| 字段 | case-001 | case-002 |
|------|----------|----------|
| `meta.id` | `case-001` | `case-002` |
| `meta.order` | `1` | `2` |
| `meta.title` | `08:17 的空档` | `08:17 的通话` |
| `meta.difficulty` | `tutorial` | `normal` |
| `meta.unlocked` | `true` | `true` |
| cover 图逻辑 | isMain=true → 渲染封面 | isMain=false → 无封面 |

`CaseMeta` 没有 hero/marketingMeta 字段，两张卡片差异仅靠 `isMain` flag 区分，而非数据驱动。

  </div>

    <p class="case-risk">风险等级：HIGH · 难度：NORMAL</p> // ← 硬编码

// 第二个 case card（app.ts:1474-1481）：

  <div class="case-card-content">
    <h3>封存中</h3>                     // ← 硬编码"封存中"占位，无条件显示

"封存中"占位卡是**硬编码**，不是数据驱动，不检测 case-002 数据是否存在。当 case-002 被选中进入 StageOneApp，archive 屏仍显示 case-001 卡 + 锁定占位，而非 case-002 的内容。

## 8. 综合判断

### 8.1 数据缺失类（case-002 data.json 缺字段）

- **Bug 7**：`chenhao-workstation` hotspot 的 `onInteract` 缺少 `{ type: "openOverlay", overlay: "inspect" }` 效果，导致点击后无弹窗反馈。
- **Bug 1**（部分）：`CaseMeta` 类型无 `hero`/`marketingMeta` 字段，case-002 meta 中无法提供封面图路径。

### 8.2 接线错误类（代码读错 caseId 或全局静态内容）

- **Bug 2**：`renderArchiveBody()` archive 主卡片内容（title、tags、meta、summary）全部硬编码 case-001，不读 `this.state.caseId` 对应 `caseConfig`。
- **Bug 3**：`renderArchiveBody()` 第二格"封存中"占位是硬编码 DOM，不判断当前 case 是什么；`renderIntroBody()` 四个 briefing block 全部硬编码 case-001 文本。
- **Bug 4**：caseId 在 state 层正确（`this.state.caseId = 'case-002'`），但 `renderArchiveBody()`、`renderIntroBody()`、`render()` status bar（app.ts:1548）均不使用 caseConfig 渲染动态内容。
- **Bug 5**：`renderIntroBody()` 不读 `caseConfig.introLines`、`caseConfig.initialObjective`、`caseConfig.characters` 等字段，case-002 briefing 永远不显示。
- **Bug 6**（主因）：`getNextActions()` 和 `evaluateFirstContradiction()` 均硬编码 case-001 专属 clue/testimony ID，`first-contradiction-found` flag 在 case-002 下永远无法触发；`preloadCriticalAssets()` 硬编码 case-001 角色文件名。
- **Bug 8**：`getNextActions()` 全文硬编码 case-001 文本，`setupIdleHint()` 硬编码 case-001 hotspot 名 + 人物名。

### 8.3 schema 不兼容类（case-002 数据结构与 case-001 不同）
