# T2.8 Case-002 Data Migration Notes

## 概览

T2.8 完成两项工作：
1. 将三份剧本文档转换为 `src/cases/case-002/data.json`
2. 新增 `unlocksSuspect`/`breakable` 多嫌疑人解锁机制并接入 `resolveEnding` 扩展条件

## Schema 扩展

### TestimonySentence（types.ts）

| 字段 | 类型 | 说明 |
|------|------|------|
| `breakable?` | `boolean` | 默认 true；false = canonical 命中触发副作用但不推进回合 |
| `unlocksSuspect?` | `string` | breakable:false + canonical 命中时，将该 suspectId 的 `unlocked` 置为 true |

### ConfrontationState（types.ts）

- `unlocked: boolean`（非可选，默认 true）：false 时 UI 显示"🔒 嫌疑人未明"，tab 不可点击

### EndingMatrixRule（types.ts）

`when` 新增字段：
- `clueInterpretations?: { [clueId: string]: 'canonical' | 'partial' | 'misread' }` — 指定线索解读档位匹配
- `submissionWrongTarget?: string` — 提交目标为此嫌疑人名称时触发

`requires` 新增字段（均满足才命中）：
- `totalScore?: string` — 格式 `>=N`，与 interpScore 比较；interpScore = canonical×2 + partial×1
- `keyCluesAllCanonical?: string[]` — 所有列出线索均选择 canonical 时满足

## 运行时逻辑

### 初始锁定推导（enterConfrontation）

遍历所有 suspects 的所有 sentences，收集 `breakable === false && unlocksSuspect != null` 的目标 ID，对应 suspect 初始 `unlocked = false`。

### presentEvidence breakable:false 路径

```
canonical 命中 + breakable === false:
  1. 显示 onCorrectFeedback
  2. 若 unlocksSuspect → confrontationBySuspect[target].unlocked = true
  3. 清空 selectedSentenceId
  4. 不改变 roundIndex / roundResults（回合不推进）
```

### resolveEnding 扩展条件求值顺序

1. `when.submissionWrongTarget` — 优先匹配错误指控路径
2. `when.clueInterpretations` — 特定线索解读组合
3. `when.submissionCorrect + requires.totalScore + requires.keyCluesAllCanonical`
4. `when.minScore` — 分数门槛（旧字段，case-001 兼容）
5. `endingMatrix.fallback`

### canAccuse 作用域

T2.8 收窄为仅检查当前嫌疑人（`currentSuspectId`）的 roundResults，要求至少一回合 won/draw。
